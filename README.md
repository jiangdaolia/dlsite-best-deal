# DL Price Tracker + DLsite 优惠助手

## 项目来源

本项目直接基于 [syoius/dlTracker4TamperMonkey](https://github.com/syoius/dlTracker4TamperMonkey) 修改和扩展；该项目又基于 [Cassandra-fox/dlTracker](https://github.com/Cassandra-fox/dlTracker) 改写。因此，`syoius/dlTracker4TamperMonkey` 是本项目的直接上游，`Cassandra-fox/dlTracker` 是间接上游。

本项目继续遵循 MIT 许可证，并保留原作者署名。史低和公开价格走势数据来自 [DLwatcher](https://dlwatcher.com/)。

## 功能概览

- 在 DLsite 的作品详情、搜索、分类、排行、活动、社团、收藏和购物车等页面显示当前日元价、史低和价格走势入口。
- 购物车底部的浏览历史、最近查看和最近售出等推荐卡也显示单作品史低、本次可到、适用优惠券与平台活动，但绝不计入购物车金额、件数或门槛。
- 自动读取平台活动和账号优惠券，显示适用折扣、件数/金额门槛、可用次数和中国时间到期时刻。
- 计算每部作品的“本次可到”理论价；购物车中另用状态按钮显示门槛差额和拼单推荐。
- 购物车价格优先显示人民币（日元）；换算比例优先来自当前作品的 DLsite 结构化 CNY/JPY 现价，缺失时才回退到购物车的可靠价格样本。
- 浏览列表和“稍后再买”支持“最高可达到折扣”“理论低价优先”与“平台折扣失效时间”排序，并可按需要凑件的具体活动或优惠券筛选。
- 列表原本未显示声优时自动补全；不依赖其他作品就能取得理论最优价时显示 `单买即最优`。
- 比较同一作品的日语、简中、繁中、英语和韩语等版本，按各自理论最低价判断更优惠的语言，并提醒已经购买或已在购物车中的其他语言版本。

## 功能详情

### 普通作品卡分析

搜索、指定条件搜索、排行、活动、收藏及页面推荐区等普通作品卡统一在原生标签区下方显示`本次可到`、`史低`、`趋势`三个小框。桌面横向宽卡的前两框显示人民币（日元）和 OFF，并与趋势框排在同一行；竖向/窄卡自动隐藏金额，只显示 OFF。手机端（包括横屏）无论原卡是否横向，三个框都改为一行一个。移动布局依据 DLsite 自己的`-touch`路由或浏览器的触控输入特征启用，不依赖固定屏幕像素。横向卡保留 DLsite 为封面图片预留的原生内容缩进，助手宿主只改用自动宽度，让浏览器按“卡片宽度减去图片占位”计算空间，既不越界也不挤入图片区域。数据尚未取得或没有史低时仍显示读取/缺失状态。下方用小字显示最多两种可用优惠券和适用平台活动；券与活动是独立的自适应内容组，空间不足时在项目之间自然换行，单条长文案也沿用 DLsite 的`overflow-wrap`方式在卡片边界内断行，不会撑宽页面。手机端同时缩短分析区与本卡内容的上间距，并增加底部留白，使优惠信息在视觉上明确归属于上一张作品卡。分析块不插入标题、图片、价格或原生按钮区域；找不到标签区时才追加到原生卡片内容末尾。脚本会跳过搜索页的加载骨架，只增强真正包含作品的结果列表。购物车“立即购买/稍后再买”仍使用专用五框布局和完整金额。

### 价格、史低与本次可到

- 支持 DLsite RJ（同人）/BJ（乙女）作品页、收藏页、购物车和常见作品浏览列表。
- 中文等本地化价格后补充精确的当前日元价，并保留上游的史低标签和“查看价格趋势”链接。
- `本次可到` 以原价为基准：当前平台折扣与多件活动取更便宜的一项，再与一张最优适用券按规则叠加。例如 `60% OFF` 后再用 `50% OFF` 券，综合为 `80OFF`。
- 本次可到价不高于史低时使用金黄色，高于史低时使用蓝灰色。
- `满1,200减400` 在单作品标签、排序和未凑齐作品的理论总价中按约 `33OFF` 表示；当前可结算价则按每笔订单满1,200日元精确减400日元。

### 语言版本比较、已购与购物车提醒

购物车的立即购买和稍后再买作品、以及作品详情页均提供`比较语言版本`入口。桌面购物车中的入口只放在原生操作容器内部，与原生`稍后再买/放回购物车`按钮宽高一致、左边缘对齐并位于正上方，不参与作品标题行的宽度分配；手机端则显示为原生操作左侧的可点击文字，不增加醒目的按钮。脚本从当前详情页的 DLsite 官方语言选择数据取得同一作品的语言母编号，再批量读取价格和翻译子商品；不会逐个打开其他语言详情页。没有其他语言时，入口会变为不可点击的`无其他语言`。

比较弹窗使用七列：`语言｜作品｜人民币/日元｜现在/平台/史低｜备注｜看详情｜购物车`。每种语言一行，作品列显示语言母编号；理论最低价可以包含尚未满足门槛的活动或优惠券，平台列只显示当前无门槛直降，史低严格使用该语言母编号自己的 DLwatcher 数据。当前语言固定第一行，其他语言按理论最低日元价升序；最低价行高亮，已购买或停售行优先标灰。价格及“现在”可以点击查看现有的本次可到计算链。表格按内容决定列宽并尽量不换行，空间不足时只在表格区域横向滚动。

翻译语言可能包含多个实际译者子商品。只有一个在售译者时可以直接加入；多个译者时必须先选择，脚本不会静默代选。加入全新版本使用 DLsite 当前前端的官方单商品购物车操作；在购物车页加入后会自动刷新页面并恢复同一语言比较弹窗，不需要用户重新点击。放回稍后再买或永久移出时按实际翻译 SKU 精确触发该商品的原生操作；永久移出的确认会同时写明语言、语言母编号和实际商品编号。任何操作都不会自动替换其他语言、批量执行或自动重试。

首次登录且没有本地索引时，脚本读取一次购物车和已购清单，并按日文原作编号建立语言家族索引。普通作品卡命中索引后，会在助手分析区顶部显示`已购买`、`已购买日语版`、`已在购物车`或其他语言版本的理论价格比较；提醒可以点击打开完整语言表。提醒在后台计算完成后一次替换，内容没有变化时不会重建，也不会由助手自身的 DOM 变化触发整页重算；外层优惠分析重新渲染时会直接迁移已有购买状态节点和标灰状态，不先删除再添加。浏览排序区提供分开的`隐藏已购买`和`隐藏购物车/稍后再买`开关；后者按整个语言家族判断，任一语言版本已在购物车或稍后再买都会隐藏当前卡片。两个开关独立持久保存，并与凑单筛选合并。`账号信息`面板显示立即购买、稍后再买、已购买数量、语言索引进度和上次读取时间，并提供`读取购物车和已购清单（请勿频繁读取）`。基础清单读取成功后面板会立即更新，再继续显示如`语言索引：0/88（读取中）`的进度；账号语言元数据每批40部，严格串行且批次之间等待10秒。页面刷新、跳转或缓存恢复造成中断时，下次启动会利用已缓存的成功批次自动续接；若因403、429或验证页安全停止，则持久显示暂停原因与剩余项目，不自动重试，仅在用户等待一分钟后明确手动读取时开始新会话。全部结束但有项目未取得时显示明确失败项数。

公开作品信息批量请求明确不携带登录 Cookie 且不发送来源页；购物车、已购清单和优惠券仍只在必须识别当前账号时使用登录态。账号语言索引在当页价格与优惠渲染完成后再后台串行读取，批间等待不再阻塞购物车或浏览页交互。账号索引使用独立的请求熔断状态：优惠券或当页分析失败不会阻止账号索引，账号索引自己触发403、429或验证页时也只暂停该索引。

语言关系缓存24小时，价格、活动和理论价缓存30分钟。完成购买后自动刷新已购索引一次，平时不轮询。退出或切换账号会清理旧索引；本地索引和诊断文件都不保存账号名、邮箱、Cookie、认证请求头或原始账号编号。

### 购物车卡片与双弹窗

购物车每部作品的 DLsite 原生作品行下方显示 5 项优惠摘要：`本次可到`、`史低折扣`、`平台折扣`、三态状态按钮和`价格趋势`。脚本把原生图片、标题、价格及价格右侧的`稍后再买/放回购物车`视为不可拆的整体，不向其中插入节点，也不修改其父容器布局。桌面端仍为一行五框，前三个价格框等宽，金额使用人民币/日元紧凑格式，例如`约45.43元/1,078円`。手机端改为弱化边框的两行摘要条：第一行是本次可到、状态和趋势，第二行是史低与平台折扣；只有可点击项保留轻量按钮感，较低价格只高亮文字和 OFF，不再整块铺色。
“本次可到”与史低中谁更便宜，谁使用金黄色高亮；价格相同时两框都高亮，无史低时不做胜负高亮。
购物车中不再向 DLsite 原生人民币价格后追加日元，日元价格统一在上述价格框中查看，不改动原生价格行的布局。

- `本次可到`按钮只解释当前作品的官方原价 → 平台层优惠 → 本单优惠券 → 理论最优价、综合 OFF 和史低对比。
- 弹窗的“节省”以作品平台当前折扣价为基准，明确显示本次可到还能节省的人民币与日元金额，不以官方原价或史低作为该项基准。
- 史低对比会明确写出“比史低便宜”或“比史低贵”的差额，并同时显示人民币与日元；价格相同时直接标明。
- 状态按钮在`需凑单`、`门槛已满足`和`单买即最优`之间切换。它的弹窗负责购物车总计、已满足门槛、还差金额/件数、当前与理论最优总价的差额，以及需要时的拼单推荐。
- `单买即最优`弹窗只简要说明不需凑金额/件数、所用平台层和优惠券，不显示拼单推荐。
- 两个弹窗均不显示自动拆单方案。

5 框下方分别以`可用优惠券`和`平台活动`为标题显示表格，每种券或活动占一行。券表为`折扣｜使用条件｜可用次数｜到期（中国时间）`，默认只显示前 2 种，其余可点击展开或收起；活动表为`活动条件｜到期（中国时间）`。条件与进度合并显示，例如`满1200-400·还差300円`、`3件60OFF·可用`。表格优先自适应内容，超出作品宽度后仅表格区横向滚动；无对应优惠时整区隐藏。

状态弹窗中的拼单推荐规则如下：

- 从“稍后再买”按当前作品的最高券和平台活动给出拼单推荐。候选必须当前平台价不高于史低；缺少史低、超出目标券范围，或存在券层等效 OFF 更高的适用券时不会进入该券的候选。平台活动候选不受“更高券”排除规则影响。
- 满件数券和平台活动列出全部合格候选，不默认选择或计入总价；按综合 OFF、结算价和原顺序排列，默认显示前 10 部并可展开全部。同时需要活动与券时，每部候选都必须命中两者。
- 满额券先最小化超出门槛的金额；超额相同时优先更多作品，再比较实际结算总价、综合 OFF 和原顺序。每张并列最高券默认显示 1 个方案，可展开另外 2 个备选。方案总计中的“优惠前”采用平台折扣或平台活动后的价格合计，“优惠后”再扣除本单优惠券。
- 推荐表固定显示作品、人民币/日元、现在/平台/史低、备注、看详情和加购物车。“现在”按最终结算价相对原价计算；本单实际使用的一张优惠券写在方案总结里，备选作品的其他同档券和适用平台活动写在备注里。六列的表头与内容统一上下居中、向左对齐，并按内容自适应宽度、不强制等宽；超出弹窗后仅表格区横向滚动。价格横向写成`约5.32元/126円`，三种折扣写成`93OFF/90OFF/90OFF`并高亮力度最大的一项；并列最大时一同高亮。
- 推荐表的“加购物车”只在用户点击后触发该作品现有的 DLsite 原生 `.link_move_cart` 操作，一次处理一部；不伪造私有接口，也不提供批量自动加入。按钮文字会因语言或手机布局变化，因此只作为兼容兜底，不作为唯一识别条件。

每笔订单最多使用一张优惠券。

弹框的详细注意事项默认折叠；打开后背景页面停止滚动，只允许弹框内容滚动。弹框在后台完成计算后一次性更新，数据未变时不重复渲染，避免频繁闪烁。点击弹框外部、关闭按钮或按 `Esc` 可关闭。所有方案都只读展示，不会自动移动作品、套用优惠券或提交订单。

### 优惠券与平台活动

- 支持指定作品、社团、站点、作品类型和隐藏分类等结构化适用条件。
- 支持百分比券、固定减免券、满减券、一次性券和期限内可重复使用券。
- 同业务规则的多张券合并显示，但保留实例数量、使用次数和最早到期时间。
- 当前平台折扣与多件活动二选一；优惠券可与其中一项按规则叠加，优惠券之间不叠加。
- 多件活动优先使用结构化结束时间。日本时间 9 月 3 日 13:59 会显示为中国时间 9 月 3 日 12:59；如果只取得日期而没有时分，不自行虚构 `23:59`。

### 浏览列表排序、筛选与声优

脚本不修改 DLsite 原生排序下拉框，而是增加独立的“优惠助手排序”：

- `保持 DLsite 当前顺序`：恢复当前页面的原始顺序。
- `最高可达到折扣`：按理论最大 OFF 降序。
- `理论低价优先`：按“本次可到”理论日元价升序。
- `平台折扣失效时间`：只比较当前平台直降的结束时间，最早失效的作品排在前面；没有平台折扣或结束时间未确认的作品排在最后。

“最高可达到折扣”和“理论低价优先”在主字段相同时优先显示当前平台价不高于史低的作品；“平台折扣失效时间”相同则直接保持 DLsite 原顺序。“稍后再买”保留排序总开关，开启后提供这三种排序。

浏览控制区另有`隐藏已购买`按钮。启用后，当前语言已购或其他语言版本已购的作品都会隐藏，按钮改为`显示已购买`；再次点击即可恢复。选择会保存在本地，并与`凑单优惠`筛选同时生效。

排序控件在异步补全价格和优惠数据时保持原节点，不会反复重建或移动；macOS Chrome 展开原生下拉菜单后可以正常停留并选择。

从浏览列表进入作品详情后再使用浏览器返回时，脚本会识别页面缓存恢复，重新应用此前保存的优惠助手排序和凑单筛选，不需要重新选择。

“凑单优惠”筛选包含全部作品、所有需要凑件的优惠，以及每个具体的多件活动或件数券；选项中同时显示购物车件数进度。“稍后再买”使用同一套筛选选项和已选状态，并可与两种排序同时生效。纯金额门槛券不进入该筛选。

在手机版作品页中，排序与“凑单优惠”控件固定显示在主“作品一览”上方，不会误挂到页顶热门排行区。控件会先显示，具体活动和优惠券选项在异步数据读取完成后补全。

如果当前列表卡片未显示声优，脚本会从当页批量作品数据中补全全部声优，不为每部作品单独打开详情页。分页、无限滚动或 SPA 追加新作品后，会重新应用声优补全、筛选和排序。

### 购物车门槛与动态更新

- 只有“立即购买”作品参与满减金额、件数券和多件活动门槛。
- “稍后再买”作品仍显示自身的“本次可到”和适用优惠，但不增加当前金额或件数，仅用于排序和拼单推荐。购物车页会同时扫描“立即购买”和“稍后再买”，不套用普通浏览页的主列表限域。
- 满额券的拼单推荐只从当前已达或低于史低、符合目标券范围且没有更高券层优惠的作品中选择；先减少超额，同超额时优先更多合格作品。每张券最多保留 3 个方案。
- 快照分别保存“立即购买”和“稍后再买”。作品新增、删除或在两个区域之间移动后，脚本会重算价格、门槛、推荐和排序。
- 在其他页面打开计算弹框时使用最近的购物车快照，并显示更新时间与可能过期的提示；不定时轮询购物车。

## 自动读取、缓存与安全

- 优惠券缓存区分“从未读取”和“已成功读取 0 张”。只有无缓存、已知优惠券到期、成功购买、账号变化或主动打开“我的优惠券”页时才刷新，不定时轮询。
- 作品元数据缓存 30 分钟，每批最多读取 100 个尚未缓存的作品编号。只有当页无限滚动或 SPA 载入新作品时才读取后续批次，不预取其他分页。
- 脚本直接使用优惠券接口返回的结构化条件，不打开券详情，不翻动数千部适用作品的分页，不逐作品访问详情页。
- 多件活动只按作品的 `bulkbuy_key` 读取和缓存规则，不枚举整个活动的作品列表。
- 遇到 HTTP 403、429、验证码或异常 HTML 时，立即停止当页后续 DLsite 自动请求，不自动重试。
- 自动读取只使用低频同源请求；脚本不会自动加购、换语言、套券或下单，也不访问第三方翻译或 AI 服务。只有用户明确点击语言表中的购物车操作时，才会对一个实际商品执行一次 DLsite 官方前端使用的加入、放回或移出动作。无法承诺零风控风险，实际结算仍以 DLsite 为准。

## 独立优惠券读取器（诊断用）

**[安装优惠券读取器 B 版](https://raw.githubusercontent.com/jiangdaolia/dlsite-best-deal/main/userscript/dlsite-coupon-reader.user.js)**

`userscript/dlsite-coupon-reader.user.js` 是诊断/验证工具，不是日常使用的主入口。它会在“我的优惠券”页面读取和诊断当前账号的优惠券，并在购物车页读取必要的批量作品条件。它不请求 DLwatcher，不打开优惠券详情，不翻适用作品列表。

诊断 JSON 会移除 Cookie、认证请求头、登录凭据、优惠券兑换码、邮箱和账号身份字段，但会保留真实优惠券 ID，因此不要公开上传诊断文件。主脚本和读取器同时启用时会在购物车页产生重叠读取与展示；日常使用建议只启用主脚本。
